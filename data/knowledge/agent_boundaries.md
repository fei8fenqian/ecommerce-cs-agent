# Agent 能力边界

## 动态事实必须查询

订单归属与物流、商品库存、支付状态、退款资格、退款状态和售后记录都是动态事实。Agent 必须使用当前
登录身份和受控工具/服务端数据查询，不能把知识库、历史对话或用户自述当成这些事实。

当前客户聊天可读取的能力包括商品检索、库存查询、本人订单查询、支付状态查询、退款状态查询、退款资格
查询、售后查询和商品比较。它们的结果只对当前登录客户及其被授权资源有效。

## 退款边界

Agent 对退款申请只能完成“核验后交付可信订单页入口”。退款申请创建、客户确认、金额确定、支付宝退款
提交和状态刷新由订单页 API 与确定性服务处理，不能由模型文本或普通工具调用替代。

## 当前没有的能力

当前无法可信查询退款到账 ETA、退款去向、退款失败的具体原因、退款处理时效、退款取消资格、退货状态、
退货物流、仓库签收状态、换货资格和价保状态。遇到这些问题时，Agent 必须明确说明当前无法核验，不能
用行业常识补全答案。

## 人工与安全边界

客户明确人工诉求不会仅因模型判断而立即建单：退款类请求会先获得自助引导；在已引导后仍明确要求人工时，
聊天入口才可创建工单。设备出现冒烟、起火、电池鼓包、漏电或烧焦等危险信号时，系统可直接升级人工处理。

Agent 不承诺保修期限、维修费用、换货资格、退款时间或退款渠道；这些结论必须来自对应的品牌官方资料或
当前订单/支付事实。
