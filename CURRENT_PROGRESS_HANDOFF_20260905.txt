2. Product recommendation 已解决
============================================================

此前真实问题：
- 第一轮推荐链接正常，第二轮手机/配件可能没有详情链接；
- LLM 可能自行拼假的 product id；
- present_product_candidates 没调用时，后端会再次调用 Operator；
- SSE 第一版回答结束后又被第二版覆盖。

已收口：
- authoritative Catalog 先形成 server-owned candidate frame；
- ProductResolver 在 frame 内返回有序 opaque candidate_N；
- Server 验证 candidate membership，并映射 canonical catalog product_id；
- 商品详情 URL 只由 Server 生成；
- Operator 不再拥有 canonical identity / URL authority；
- recommendation main path 不再依赖 present_product_candidates；
- 删除“缺 presentation declaration -> 第二次完整 LLM 回答”的主路径 retry；
- ProductContext.choice_refs 复用已有 server-owned frame，支持“对应链接呢 / 第二个”等连续对话；
- laptops / phones / components 走同一条通用路径，没有品类特判。

用户真实 E2E 已确认：
- 笔记本推荐链接正常；
- 手机推荐链接恢复；
- 推荐 SSE 不再被第二次完整回答覆盖；
- 用户反馈推荐整体表现很好。

3. Refund subject continuity 已解决
============================================================

此前真实问题：
“我想退华为” -> 多订单 -> “我搞错了，我想退 iPhone”
会 generic unresolved。

真实 trace 已证明 SupportCommand 本身理解正确：
- set_subject("iPhone")
- command_cutover=true
- workflow_authority=support_command

最终根因不是 LLM/Case，而是 track_order 大结果超过 SupportWorkflow persistence bound 后被退化为 summary，订单身份丢失，OrderSubjectResolver 无候选可绑。

已收口：
- 大的 authenticated order list 投影为 compact server-owned order candidate frame；
- 最多保留 10 笔身份；
- 从 checkout items[] 提升 product_name / catalog_category / component_category / catalog_product_id 到候选顶层；
- 优先删除冗余 decoration，不先删除订单 identity；
- compact frame 仅用于 identity binding；
- 绑定订单以后退款状态/资格/入口仍由现有 Tool / Provider fresh-read；
- 没有新增 Case state / RefundCommand / 审核状态 / Manager。

用户真实 E2E 已确认：
1. “我想把刚买的华为退了” -> 正确出现 3 笔 Huawei；
2. “我搞错了，我想退的是 iPhone” -> 正确切换到真实 iPhone 候选；
3. 选择 iPhone -> 正确核验退款资格并给官方自助退款入口；
4. “我已经申请退款了，你看看成功没” -> fresh-read，正确返回等待商家核验及退款金额；
5. 普通 acknowledgement “好的了解” -> 正常自然回复；
6. “之前的华为还是想退了” -> 正确重新发现 Huawei 候选；
7. “我点错了，我想退的是另一台华为” -> 正确重新得到 Huawei choice frame，可再次选择不同订单。

因此“退款对象改错后无法重新绑定”的主故障已经真实 E2E 解决。

4. 本轮最后一个 presentation 小问题及修复
============================================================

真人 E2E 最后残留：
用户已经通过结构化 choice 点击并绑定，例如：
SO20260904034942C4A0A2478CFB

Server 同轮已经有：
- selected_subject_present=true
- track_order success
- query_refund_status success
- workflow outcome COMPLETED / ANSWER

但 Operator prose 仍可能说：
“请问您想退哪一笔华为订单？请回复序号或订单号……”
随后下方又正确展示当前订单退款状态。

根因：
customer-response boundary 原本会校验退款状态/资格事实是否矛盾，但没有校验：
“Server 已经绑定 subject” 与 “Operator 又要求客户重新选择 subject” 的 presentation contradiction。

本轮最小修复：
- 只修改 customer-response safety boundary；
- 当 authoritative subject_id 已存在时，若 Operator prose 又要求提供/回复/选择/确认是哪笔订单，则视为与 server-owned identity 冲突；
- 不保留该 prose，回退到已有 deterministic refund fact renderer；
- 正常、与事实一致的自然语言状态解释继续保留。

这不是 Router/语义判断，不影响用户意图；只是 final presentation 对 server state 的一致性校验。

Production 本轮仅修改：
- src/agent/customer_response.py

Tests 本轮仅修改：
- tests/test_customer_agent_boundary.py
